# ZEDER Search · Seaside Workshop

고객은 하단 중앙의 대화창에서 요청하고, 장인은 그 요청과 응답 상태에 맞춰 공방 안에서 움직입니다. 전략 문서와 대화 기록은 필요한 때에만 펼쳐 봅니다. 마케터 스튜디오는 별도의 2D 화면입니다.

## 현재 경험

- 실제 Three.js 공방, TOMOB에서 참고한 파도, 낮·노을·밤, 마우스에 따른 제한된 카메라 회전.
- 새 요청을 받으면 주문서를 확인하고 보드·선반·작업대로 이동합니다. 행동 선택은 입력 키워드와 요청 상태를 연결한 1차 시각화입니다.
- 응답이 질문이면 사용자 입력을 기다립니다. 전략 버전이 생성되면 문서를 운반·제시하고, 작업대의 `전략 열기`와 대화창에서 같은 결과를 확인합니다.
- 결과는 애니메이션이 끝나기 전에도 바로 확인할 수 있습니다. 중지·실패·검토 대기 상태를 완료로 표시하지 않습니다.
- 사용자가 캐릭터를 조종하거나 도구를 찾아다닐 필요는 없습니다. 시스템의 동작 줄이기 설정도 지원합니다.

구현과 상태 전이: [Request-driven workshop](docs/WORK-DIRECTOR.md). 이전 `docs/ISLAND.md`는 초기 섬/탐험 시안의 기록이며 현재 고객 조작 방식은 아닙니다.

## 실행

Node.js 22 이상이 필요합니다.

```bash
npm install
npm run dev
# http://localhost:3000
npm test
npm run build
node scripts/preview.mjs
# preview.html: Three.js와 리소스를 포함한 단일 파일 예시 프리뷰
```

빌드는 고정 버전 Three.js 0.169.0과 출처/해시가 지정된 표면 리소스를 준비하고 `dist/`를 만듭니다. API 함수는 `api/chat.js`에 남습니다.

## 화면

| 경로 | 역할 |
| --- | --- |
| `/#/` | 공방과 첫 입력창 |
| `/#/chat/:id` | 공방과 하단 대화, 선택해서 여는 전략/기록 |
| `/#/request/:id` | 같은 공방에서 요청 상태와 검토본 확인/승인 |
| `/#/requests` | 저장된 대화와 요청 목록 |
| `/#/studio` | 별도 마케터 요청함 |
| `/#/studio/:id` | 구조화된 전략 편집·검토 제출 |

## 예시 모드와 실제 연결

현재 인증정보 없는 버전은 **예시 모드**입니다. 응답은 규칙 기반 시뮬레이션이며 실제 LLM 결과가 아닙니다. 캐릭터의 노트 읽기 동작도 인터넷 조사가 수행됐다는 뜻이 아닙니다.

실제 LLM 연결은 `.env.example`을 참고해 서버에만 `OPENAI_API_KEY`, `OPENAI_MODEL`, 16자 이상의 무작위 `ZEDER_PREVIEW_KEY`를 설정합니다. 화면에는 테스트 접근 코드만 입력합니다. API 키를 화면이나 저장소에 넣지 마세요. 라이브 모드에서는 대화·첨부가 OpenAI API로 전송됩니다.

서버는 요청 스키마·출력 형식·접근 코드·기본 호출 제한·시간 제한을 검사합니다. 모델 오류를 예시 성공으로 바꾸지 않습니다. 사용자 중지와 이전 요청의 뒤늦은 응답도 구분합니다.

## 데이터와 실행 범위

대화·요청·검토는 해당 브라우저의 localStorage에만 저장됩니다. 고객/마케터 전환은 같은 브라우저의 역할 체험이며 계정 인증이나 계정 간 협업이 아닙니다. 중요한 기록은 대화 기록에서 내보내세요.

고객 검색, 실제 마케터 매칭/전달, 이메일·DM 발송, 광고 집행, 외부 게시, 결제와 정산은 연결되지 않았습니다. 승인 후 도구가 제공하는 것은 명시된 템플릿 초안입니다. 운영 전에는 로그인, 워크스페이스 격리, 영속 저장, 분산 사용량 제한과 필요한 정책을 추가해야 합니다.

## 검증

현재 로직·스키마·저장·HTTP·씬 테스트 103개가 통과했습니다. `tests/browser.mjs`는 실제 HTTP 접속, 브라우저 저장소와 Chromium WebGL로 입력→캐릭터 이동→전략 확인→중지/재시도→검토/승인→복원을 검사합니다. CI에서는 Playwright와 Chromium을 설치한 뒤 실행합니다. `BASE_URL`과 `EXPECT_COMMIT`으로 특정 배포를 검사할 수도 있습니다. 결과는 해당 GitHub Actions 실행에서 확인하세요.

로컬 환경의 브라우저 탐색 제한이 있는 경우 별도의 번들/메모리 저장 어댑터 검사를 사용했습니다. 이는 실제 HTTP 검사와 구분하며, 애니메이션 체크포인트는 실시간 FPS 측정이 아닙니다. 생성한 컨셉 이미지와 모델의 디테일 수준이 같다고 주장하지 않습니다.

## 배포

저장소의 `vercel.json`은 Framework `Other`, Build `npm run build`, Output `dist`와 서버 함수 구성을 사용합니다. GitHub 반영과 Vercel 배포는 별개입니다. 이번 동작 구현 커밋의 공개 배포 여부를 실제 URL에서 확인해야 합니다. 환경변수 없이 실행하면 예시 모드이며 유료 모델을 호출하지 않습니다.
