# UX v0.2 — 고객에게는 대화, 마케터에게는 작업 공간

## 이번 변경의 이유

이전 구조는 고객에게 예산, 타깃, 가설, 채널, 도구를 먼저 선택하도록 요구했다. 이는 마케팅을 맡기려는 사용자에게 마케터의 역할을 떠넘긴다. 고객의 첫 행동은 한 문장으로 상황과 고민을 말하는 것으로 끝나야 한다.

## 고객 흐름

1. 첫 진입: 큰 질문과 입력창 하나. 예시 문구는 입력을 돕기만 하고 자동으로 요청하지 않는다.
2. 대화: 이미 말한 정보를 재질문하지 않는다. 꼭 필요한 질문만 한 번에 하나씩 한다. 모르는 항목은 가설로 제안하고 가정임을 표시한다.
3. 전략: 목표와 실행 경로를 대화 속 카드로 제안한다. 필요한 도구는 경로에 자동으로 붙는다. 도구 칩은 준비할 내용을 설명하는 상세보기이지 고객이 빈칸을 채우는 선택기가 아니다.
4. 고객 결정: 대화로 변경하거나 `전략 요청`을 누른다. 확인 모달에서 목표·타깃·예산을 요약하고 별도로 확정한다.
5. 요청 이후: 진행 상태를 보여준다. 존재하지 않는 담당자, 응답 시간, 성과 수치를 표시하지 않는다.
6. 검토본 도착: 변경된 전략과 검토 메모를 보고 승인하거나 수정 요청한다.
7. 실행 준비: 승인된 버전으로 필요한 초안을 준비한다. 자료 준비와 실제 발송·게시·예산 지출은 다른 상태이며 현재 외부 실행은 미연결이다.

## 마케터 흐름

전용 `/#/studio`에서 요청 대기열을 확인한다. 고객의 전체 대화와 사업 요약은 읽기 전용이다. 타깃·목표·예산·가설·실행 경로·도구·검토 의견을 편집하는 폼은 마케터 영역에만 노출한다. 검토 초안 저장은 고객 제안을 바꾸지 않는다. 제출은 새로운 전략 버전을 생성한다. 고객의 승인 전에는 실행을 시작하지 않는다.

## 상태 계약

`draft → requested → reviewed → preparing`

- submittedVersion: 고객이 요청한 정확한 버전
- reviewedVersion: 마케터가 제출한 버전
- approvedVersion: 고객이 준비를 승인한 버전
- 나중의 대화 초안이 이미 제출한 버전을 덮어쓰지 않는다.
- 중복 제출 및 중복 준비는 같은 버전에서 중복 부작용을 만들지 않는다.
- 마케터 편집 시작 후 요청 버전이 바뀌면 오래된 제출을 거부한다.
- 검토본 수정 요청은 다시 requested 상태로 돌아간다.

## LLM/예시 모드의 경계

실모델은 대화 정책과 JSON Schema에 따라 사업별 1~4개 경로를 제안한다. 특정 채널이나 3개 카드 조합을 의무화하지 않는다. 실제 조회 도구가 없으므로 URL·경쟁사·리드·성과를 조사했다고 주장할 수 없다.

예시 모드는 연결 전 UX 검증을 위한 규칙 기반 시나리오다. 화면, 대화 메시지, 결과 가정에 이를 표시한다. 모델 장애가 발생했을 때 예시 답변을 실제 응답처럼 돌려주지 않는다.

## 비목표

첫 진입 대시보드, 사용자용 ICP/KPI 폼, 빈 실행 슬롯, `도구 추가` 강요, 사용하지 않은 크레딧 차감, 가상 성과 그래프, 미구현 자동 고객 발굴, 과장된 대행 완료 알림을 만들지 않는다.

## 후속 구현

상용 인증과 역할 권한 → 서버 워크스페이스 및 생성 이력 저장 → 실제 마케터 전달/알림 → ZEDER Runner 연동 → 실행 승인 계약과 예산 한도 → 관측된 성과 수집 순서로 확장한다. 현재 로컬 협업 체험을 실제 역할 격리나 SaaS 운영으로 오인하게 만들지 않는다.

## 문구 정리 — 2026-09-25

첫 질문, 입력창, 시작 예시만 남긴다. 소개문·단계별 사용법·슬로건·장식 배지·반복적인 보조 설명은 화면에서 제거한다. 고객 대화 → 전략 제안 → 검토 요청 → 검토본 확인 → 준비 승인 흐름은 바꾸지 않는다.

전략 자체의 타깃·예산·가설·실행 내용·근거·도구는 지우지 않는다. 고객이 판단할 실제 내용이며, 화면 사용법과 구분한다. 마케터 스튜디오에서도 편집 필드와 요청 맥락은 유지하되 기능을 설명하는 카피는 삭제한다.

예시 응답, 로컬 저장·협업 제한, 미검증 정보, 미연결 실행, 별도 승인 안내는 짧은 상태 표시로 유지한다. LLM 연결 시 대화·첨부의 외부 전송 안내도 유지한다. 서버 설정은 연결 정보 안에 접어둔다.

기존 대화와 전략 버전은 보존한다. 예시 답변과 서버 프롬프트의 새 응답만 짧게 조정한다. 모델 API 계약·데이터 스키마·권한·배포 설정은 변경하지 않는다.
